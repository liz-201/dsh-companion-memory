# dev.4 记忆文件与云端同步验证

当前版本 0.3.0-dev.4。Codex 整合记忆管理页、完整迁移入口、启动同步、凭据隔离、生命周期及回归；DSH 内 DeepSeek 实现百度客户端并定向验证，随后交还文件供 Codex 复核。没有用桌面点击代替开发协作。

## 已验证

- 全量 259 项通过，0 失败、0 跳过。包含实际 DSH Cordis/提示词模块的装配回归。
- 实际 Cordis 中先加载插件、后提供 webServer：记忆管理页与诊断路由能自动挂载；webServer 卸载移除路由，再加载后重新挂载；插件卸载无路由残留。
- HTTP 管理页实际导出下载和上传导入，页面脚本按钮工作流，以及 owner 命令权限。
- 使用实际 BaiduClient、独立协议模拟器、真实本机 HTTP 管理路由，完成设备授权 → 完整快照上传 → 下载回读 SHA-256 → 第二实例启动自动导入。
- 模拟器强制要求设备码申请的 response_type、响应分片序号、正确的 filemetas 分组、逐级创建父目录与分片内容 MD5。避免测试只复述客户端实现。
- 新 DSH 实例恢复期间到来的消息等待同步，导入后绑定云端主人；首次初始化的主动发送设备归属沿用云端，用户主动接管仍保留正常冲突规则。
- 两设备离线新增均保留、删除传播、超过检查点窗口后已有行更新、时间戳相同仍检查实际内容、无变化不重复上传。
- 上传失败、回读不一致保留本地；上传期间新写入会立即补传；断开时取消请求，授权轮询不能在断开后重建凭据。
- 百度设备码、刷新 singleflight、分片请求、秒传、分页、CDN 限制、正文超时、超限流取消等客户端契约回归。
- 用户提供应用后，真实百度设备码申请成功。首次真实请求暴露 response_type 缺失，已修复并纳入客户端及独立模拟器校验；账号持有人尚未完成设备授权，因此不能据此声称已上传真实网盘。
- 启动云端网络等待默认 15 秒后取消，继续使用本地记忆并可再次重试；不同已有主人会显示具体诊断并停止合并。
- 同一坏包针对未变化数据重试复用备份；本地数据变动后仍生成新的精确恢复备份。
- 10,000 轮确定性回放通过：20,000 原文、10,000 turns、10,000 outbox，0 断言失败。只读 doctor 0 fail / 0 warn。

## 尚未验证

应用信息已在本机配置，真实设备码申请已成功。真实百度账号设备授权、真实上传/下载及实际 DSH 重载后启动同步，等待账号持有人完成首次连接；协议模拟完整流程不能作为真实上传/下载通过的证据。真实双机/QQ、人类盲评和长期使用仍分别验收。

旧情景记忆碰撞造成的既有数据没有自动清理；不能靠新 ID 算法猜回旧内容。无共同祖先或同时独立修改同一数据时保留差异并报告；不保证任意冲突都能无损自动消解。检查点清理释放空间供 SQLite 复用，不自动压缩正在使用的生产库文件。

导入校验和事务目前同步执行。隔离环境测量 20,000 条原文导入约 1.4 秒，不能据此承诺接近大小上限的包不会阻塞事件循环；未将导入迁移到 worker。新设备应先恢复再聊天；两个已有主人不自动合并。

用户要求“确认功能按要求工作后再 push”。因此真实网盘验收完成前，代码可以在本地整理提交，远程推送保持待执行。认证信息、实际记忆文件及机器交换记录不进入提交和安装包。

## 复现

```powershell
node scripts/build.mjs
node --test "tests/**/*.test.mjs"
node scripts/replay.mjs --turns 10000
node scripts/doctor.mjs --json
node scripts/memory-transfer.mjs serve --config <隔离配置>
node scripts/package.mjs --skip-build
```

真实联动验收：管理页完成百度授权，确认已连接 → 导出自动上传且回读成功 → 本地新增一条可辨识测试记忆 → 再次同步 → 第二个隔离实例/设备启动并确认该记忆 → 重复启动确认幂等 → 离线期间修改再恢复连接 → 停止/断开确认不继续网络读写。验收前后都保留可恢复备份，测试失败不覆盖本地数据。
