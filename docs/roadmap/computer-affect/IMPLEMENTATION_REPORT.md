# 0.3.0-dev.7 实施与验证记录

日期：2026-10-26。交付级别：功能预览；不把自动测试当作模型自然度或长期用户验收。

## 已接入的行为

- 普通 DSH 与 QQ 私聊原文写入时，同事务记录一次主人回应。0、1、多条评价、迟到、重试、同毫秒消息不会重复缓解驱力。助手与界面内容不算主人回应。
- 新后台 observation-v2 输出有证据的情境向量；宿主绑定主体、原文、时间和历史引用。确定性分类覆盖 22 个 OCC 类别，以及委屈、心酸、愧疚、吃味、被重视感、安心、失落的条件化表达。普通感谢、第三方社交和没有历史依据的自身过失受到额外约束。
- 联系、探索、互动负荷与短时 PAD／慢心境按来源时间投影。读状态不写库；晚到评价、删除、修订、导入共用同一来源回放。PAD 坐标和时间常数是工程初值，尚未经过个人校准，不能解释为心理测量。
- 默认后台抽取；控制台可切换“先评估再回复”。前置超时继续回复，耐久队列稍后重试。两种入口共享一次飞行与完成标记。前置、后台、界面调用分别计量，宿主缺失的 usage 保持 unknown。
- `ExpressionPlan/renderPlan` 在桌面、QQ 与主动正文的实际装配链使用新状态；表达指导最多 150 估算 token。任务格式、原文、数字、事实与原有表达检查继续优先。
- UIA 读取指定窗口的可访问文字；窗口图像通过 PrintWindow 捕获，本机 Windows OCR 提取文字。以 HWND、PID、进程启动时间共同绑定窗口。没有全屏抓取回退。输入框按控件类型与类名排除并在图像中遮罩，处理了 DPI 坐标转换。
- 手动预览、模型分析、建立主动候选、已授权前台稳定窗口自动分析均已接入。询问当前屏幕时，可将有效的本机事实与带限定的任务解释带入回复。采集材料作为数据处理，不执行页面中的指令，不写入主人原话或自动学习成稳定兴趣。
- 默认每应用至少间隔 5 分钟、每天最多 6 次界面模型调用、15 分钟 TTL。启停、范围变化、热重载、晚返回、窗口关闭／最小化和来源过期使相应观测或待发候选失效；发送前重查窗口、系统可打扰状态及既有硬闸门。
- 控制台包含范围、选窗、预览、启停、PAD／驱力、证据、评价撤回、失败抽取重试和调用记录。新设置经严格校验，不自动扩大到其他应用。
- 追加迁移 008。回应账本与情境向量为来源，评价修订归档；成分、期待和 PAD 按需派生，未另建容易重复叠加的快照。原文删除会清除对应新向量及修订，并撤回依赖该历史行为／期待的评价。
- portable v3 支持新表、完成标记和情感参数；导入按原文重建回应账本，避免重复结算。本机范围、窗口授权、图像和局部观测排除在迁移包之外。v1/v2 仍可读；v3 需要 dev.7 或更新读取器。

## 使用

打开 DSH 的“伴侣记忆”控制台。情绪默认后台评估，可先保持默认参数体验，再切换前置模式比较等待时间。

窗口感知：填写允许的进程名，例如 `notepad`，保存并启用；列出窗口、选择具体窗口并授权，然后先预览。仅本机预览不调用模型；“模型分析”生成有依据的解释，“分析并建立主动话题线索”还会交给既有候选及发送闸门。普通提问也可以问“看看我现在的屏幕”。自动模式只处理本次启动后选定且仍在前台的窗口。

默认不上传图像。使用图像模型需要当前模型声明 image 能力，并同时选择“允许发送图像”和“允许 DSH 附件存储”。这是实际宿主附件 API 的限制：发送的图像会保留在 DSH 附件库，停止采集不删除这些宿主附件。本机 OCR 不需要这两个许可。

窗口或采集能力不可用时会明确报错或保持未知。PrintWindow 对部分浏览器、GPU 画布、受保护窗口、远程桌面不保证有效；没有声称覆盖全部应用。没有选窗时不猜测当前界面。

## 尚未作为正式验收通过的项目

- 中文浏览器／编辑器／画布／远程桌面的逐应用矩阵、混合 DPI 多显示器和锁屏／全屏全部实机场景。现有测试不证明未知应用的遮罩绝对可靠。
- WGC／常驻 helper 与当前进程式 PrintWindow 路线的完整能耗、兼容性、包体积对照；当前使用系统组件，无额外二进制依赖。
- 更长时段、可由人确认合并／拆分的跨应用任务线程。当前保留最近多次观测及限定的任务解释，不把一个进程认作一个永久任务，也不擅自把两个窗口合成同一目标。
- 真实视觉模型的画布理解、费用与延迟对照；真实 QQ 到达、两台物理电脑接管；基线／提示版／完整方案消融以及至少七天用户体验评估。
- 心境、驱力和 PAD 参数的用户校准，以及冷载入性能继续优化。热投影目标与冷启动测量分开报告。

上述项目对应原任务书 S5 和部分跨应用扩展，预览版不据此宣称“全部场景已验收”。

## 升级与回退

实施在独立工作树完成；切换生产目录前检查已有修改并保留备份。生产 SQLite 使用 Node SQLite backup API 创建一致性备份，不拷贝正在写入的单个主库文件。

回退应先退出 DSH，再一起恢复备份中的插件文件和升级前一致性数据库；升级后的新对话需先导出妥善保留。不要让只认识旧 schema 的程序直接打开已经应用迁移 008 的库。现有迁移 001–007 没有改动。所有备份均位于仓库之外的本机私有工具目录。
