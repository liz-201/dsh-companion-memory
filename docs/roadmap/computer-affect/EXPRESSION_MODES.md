# 五种任务模式的表达权限（0.3.0-dev.9 实现说明）

本文对应 `src/expression/task-mode.ts`、`src/expression/policy.ts`、`src/domain/occ-classifier.ts` 三处改动，说明「哪种输入算哪种模式」「每种模式允许注入多少连续情绪」以及「失落」的证据边界。

## 1. 判定顺序

`taskMode()` 由高到低只判一次，先命中先返回：

| 优先级 | 模式 | 触发条件 |
|---|---|---|
| 1 | `structured` | 逐字/原文/一字不改，或「只输出/返回/格式/生成 + JSON\|XML\|CSV」，或「JSON 格式/对象/数组」 |
| 2 | `creative` | 「写一篇/一段/一首/个故事/小说」「角色扮演」「虚构」「续写」 |
| 3 | `support` | 第一人称 + 情绪词，且不在引文/代码/词表语境 |
| 4 | `task` | 代码、报错、实现、插件、安装、排查、步骤、详细、方案、任务书、清单、表格、报告、计算、证明、教程、分析、怎么做 |
| 5 | `chat` | 兜底 |

三条判定约束：

- **格式契约最高**。「我现在很难过，只输出JSON」判 `structured`，不是 `support`：先满足可执行的输出契约。
- **support 必须第一人称锚定**。正则要求「我 + 可选修饰词 + 情绪词」，所以「帮我分析这段代码里的难过」「这段正则为什么匹配不到委屈」不会掉进 `support`。
- **否定与转述不触发**。「我不难过，就是有点累」判 `chat`；「他今天挺失落的」判 `chat`。引号、反引号、「比如/台词/引用/原文/这段代码|正则|文本」出现时，情绪词被视为讨论对象而不是说话人状态。

`support` 排在 `task` 之前是本次唯一的顺序调整：「我很难过，你帮我看看这个报错」现在判 `support`，以支持语气处理正事，而不是把情绪整段丢掉。

## 2. 每种模式能注入什么

`MODE_EMOTION_LINES` 是唯一权限表，`continuousDirection()` 按表裁剪，外层 150 token 预算照旧生效。

| 模式 | 条数 | 内容 | 明确不注入 |
|---|---|---|---|
| `chat` | 2 | 七条证据句按显示词命中取前 2，再补「牵挂感」「节奏放缓」 | 类别名、强度数值、PAD 数值 |
| `support` | 2 | 固定锚句 + 最多 1 条证据句 | 自己的牵挂/查岗类句子（不变成自诉委屈） |
| `task` | 1 | 只有语气余温：`drives.contact > .6` →「正事答完可多留半句，不追问」；否则「只答正事，不加寒暄」 | 任何情绪词、任何索取 |
| `creative` | 1 | 仅正向证据（显示词含 安心/被重视感，或 `pad.emotion.pleasure > .3`）→「按对方要求写，气氛可略轻快」 | 负向证据一律不进，服从用户创作要求 |
| `structured` | 0 | 与完全没有连续状态时逐字相同 | 连续情绪、驱力方向 |

七条证据句（显示词 → 指导句），每条都绑定分类器只能从评价证据里产出的显示词：

| 显示词 | 指导句 |
|---|---|
| 委屈 | 若提及不公，只说有依据的具体在意，不扩大责备。 |
| 心酸 | 可以流露具体牵挂，承认无力，不编经历。 |
| 愧疚 | 对已有证据的自身过失简短承担并落实修正。 |
| 吃味 | 关系上的在意只轻轻表达，尊重正常社交，不控制或催回复。 |
| 被重视感 | 回应对方记得的具体小事，可自然表达珍惜。 |
| 安心 | 担忧解除后语气放松，勿虚构先前担忧。 |
| 失落 | 承认没成的具体期待，只说事实，不迁怒。 |

「失落」这一行是本次补的：此前它会被算出来、占掉 `displays` 三个名额之一，却没有对应表达指导，属于白占位。

## 3. 「失落」的证据边界

- 旧实现：`disappointment` 或 `distress` 任一 → 显示「失落」。任何负面事件都会挂上它，包括纯技术报错和普通延迟。
- 现实现：只有 `disappointment`（上一轮 `prospect === 'pending'` 且 `desirability > .15`，本轮 `disconfirmed`）→ 显示「失落」。
- 理由：现有评价向量里没有「目标受阻」这一维，单凭 `distress` 无法证明「已失败的正向期待」。宁可只保留 `distress` 分量，也不猜显示词。
- 后续：若引入目标/希望受挫的显式向量（例如 `controllability` 高 + `desirability` 负 + `prospect === 'none'`），应在 `classifyOcc` 里加一条独立证据分支，而不是恢复 `|| distress`。

## 4. 验收方式

- `tests/unit/expression-emotion-modes.test.mjs`：11 项，覆盖判定顺序、support 锚句、task 语气余温、creative 只加正向、structured 等价、失落指导句、五模式 150 token 预算。
- `tests/unit/occ-disappointment-context.test.mjs`：5 项，覆盖纯负面不产失落、失败的正向期待产失落、确认不产失落、缺前置期望给 reason、其他显示词不变。
- 关键断言：`structured` 富状态与无状态输出逐字相等；`task` 在 `contact` 高低两种取值下输出不同且 0 个情绪词；`creative` 在负向证据下与无状态输出相等。

## 5. 明确不做

- 不改 `src/runtime/turn-coordinator.ts`、`src/domain/expression-plan.ts`、`src/storage/continuous-affect.ts`、版本号、`008` 迁移与生产库。
- 不采纳「亲密度下降导数的绝对值增加 passion」：该说法与所引摘要不符，会把伤害奖励成浪漫。
- `commitment` 仍是不自动启用的未来规格，不从日常闲聊推断用户未表达的承诺。
- 参数（`contactTauHours 6` / `responseRelief 0.35` / `DESIRE_REPORT_THRESHOLD 0.6` / 各阈值）继续标注为工程初值，不当作实证常数。
