## 3. 历史失败恢复的特殊要求

本机旧 extract 失败会在最终尝试后写入保守 local fallback。当前 `TurnCoordinator.observe` 对 fallback 回合恢复时会省略新事件部分，意图是防止双扣，但这也意味着仅把任务改回 pending 不足以证明完整情感抽取已恢复。

BASE02 必须区分：已经完成、仅 fallback、部分写入、已撤回和删除。对 fallback 增补语义评价时要替换或修订相同来源的评价再重建，而非再次叠加关系；补写事实记忆仍须证据校验。恢复不生成第二条聊天回复。

一次性恢复选择条件、重试预算和修改的任务 ID 应进入本机审计；报告不复制用户正文和凭据。失败则保留诊断，不把所有失败原因一并重排。恢复旧任务与验证新消息分开记录。

## 5. 交付文件与变更范围

拟新增领域模块：`domain/emotion-appraisal`、`domain/occ-classifier`、`domain/pad-projector`、`domain/drive-projector`。拟新增存储／运行模块：回应事件仓储、情感时间线回放、UIA／捕获适配器、本机观测缓存、内容分析队列。命名可服从现有仓库风格，职责与边界不可丢失。

需要更新的现有入口：`adapters/local-integration`、`runtime/turn-coordinator`、`domain/affect-projector`、`expression/runtime`、`expression/policy`、`proactive/frequency`、`proactive/computer-opportunities`、发送前闸门、`storage/portable`、删除／共享 owner 合并、控制台与 doctor。

所有类型从 `src/` 修改并通过构建产生 `lib/`；不手改生成文件，不覆盖未知的未提交修改。数据库只追加迁移；生产数据、截图、令牌、真实原文不进仓库。旧文档的冲突要求必须同步说明，不能让不同实现者各执行一套。

每个工作包提交：问题与行为、改动文件、测试结果、未测项、成本、版本、回退方式。测试夹具必须能定位到本任务书的要求 ID。

## 6. 建议实施命令

在隔离副本或开发工作树中按现有 Node 要求执行，生产插件目录为链接安装，构建和重启会影响运行版本，操作前确认当前实例任务状态：

```powershell
node scripts/build.mjs --check-only
node scripts/build.mjs
node --test "tests/**/*.test.mjs"
node scripts/replay.mjs --turns 10000
node scripts/replay-proactive.mjs
node scripts/doctor.mjs --json
```

以上仅为现有脚本。未来实施需增加感知基准、情绪场景评测、参数敏感性、完整事件回放和真实 usage 汇总入口，并提供实际用法，不将未存在的命令写成已执行。

排期按“完成条件”安排，不承诺未经估算的天数。PC02／PC03 先完成宿主集成 spike 与资源测量，再冻结依赖、安装包体积和部署方案。
