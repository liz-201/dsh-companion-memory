# 记忆文件与百度网盘同步

在 DSH 输入 `/fish panel` 或 `/fish files`，打开本机插件控制台。页面提供导入导出、百度网盘和“两台已有记忆首次配对”。导入导出不需要自己寻找或复制 SQLite/WAL 文件。

## 文件导入导出

导出的 `.companion.json` 是可直接导入的完整记忆迁移包，含原文、事实、情景、情绪/关系状态、人设、习惯、删除记录及同步所需元数据。它不携带插件程序和百度网盘凭据。导入会先建立一致性备份，检查校验和、数据库版本和所属主人，再合并；待发消息不会被复制重发。

也可使用 `/fish export`，或 `/fish import "D:/路径/记忆.companion.json"`。这些完整迁移命令仅供 owner 使用；普通会话不能导出整个记忆库。

## 首次连接百度网盘

1. 在[百度网盘开放平台](https://pan.baidu.com/union)准备自己的应用，取得 AppKey、SecretKey 及应用在 `/apps/` 下的目录名（通常为应用名称）。首次应用创建与百度账号授权必须由账号持有人完成。AppID、SignKey 不用于本插件的设备授权，不需要填写。
2. 在记忆管理页展开“首次连接或更换应用”，填写应用信息，点击“连接百度网盘”。密钥只写入本机独立授权文件，不在聊天、日志或记忆包中保存。
3. 点击页面给出的百度官方设备授权链接，输入授权码并登录授权；返回点击“我已完成百度授权”。授权成功后立即执行首次同步，并自动开启之后的同步。

支持 refresh_token 自动刷新；授权失效或权限不足会显示未完成，保留本地记忆。没有应用信息或账号授权时，功能保持待连接，不能把模拟 API 测试当作真实网盘验收。

## 自动同步流程

- 打开 DSH 时，在记忆上下文和后台工作启用前检查云端。启动阶段的网络等待默认最多 15 秒，超时取消请求、继续使用本地记忆，稍后自动重试；本地文件校验和合并仍需完成后才能放行。
- 云端按伴侣及设备分别保存快照。同步先读取云端实际内容、校验并合并，再发布本机合并结果；不单凭时间戳判断“较新”，不覆盖另一台设备的文件。
- 导出记忆后自动安排上传；运行中默认每 300 秒再次检查。无变化不重复上传。上传后会回读并核对 SHA-256，确认一致才记录成功。
- 保留已处理远端快照的共同基线，供长期离线设备回归时合并已有行的更新；检查点仍按数量和字节限制清理。超过可保留的多设备基线、双方独立修改同一条数据等情形保留冲突并报告，不丢弃本地差异。
- 断开网盘只删除本机授权、停止后续同步；保留本地记忆与网盘已有文件。DSH 退出前停止调度并等正在进行的同步收尾，不在关闭数据库后继续写入。

远程目录为 `/apps/<应用目录名>/dsh-companion-memory/<伴侣标识哈希>/`，每台设备一个 `.companion.json`。两台电脑使用相同应用和伴侣 ID，分别授权同一百度账号后即可交换记忆。设备密钥不随记忆迁移，第二台电脑需要完成一次授权。

## 配置与独立入口

首次授权会在本地设置中开启同步，无需手改 profile。需要预配置时，profile 的插件 config 支持：

```yaml
cloud:
  enabled: false
  syncOnStartup: true
  startupTimeoutSeconds: 15
  autoUpload: true
  intervalSeconds: 300
  credentialFile: ''
```

`enabled` 初始为 false；管理页授权成功后的本机开关优先。默认授权文件在 `storage.directory/credentials/baidu.json`；可单独指定路径，不能把它放进共享目录或版本控制。

新设备尚未聊天时，先导入已有电脑的记忆即可。如果两台已经独立使用过，请走下面的首次配对；重新授权网盘不会统一两个主人编号。普通导入和自动同步仍拒绝不同主人编号，只有明确确认的首次配对会统一身份。

## 两台都已有重要记忆，之前没有同步

先选一台作为首次配对的来源，下面称 A；另一台称 B。来源只决定统一使用哪个主人编号，不表示用 A 覆盖 B，也不按修改时间决定哪一边丢弃。

1. 等两台的对话生成和后台整理结束。分别点“导出并下载记忆”，保留 A、B 两份原件。不要清空任一台。
2. 在 B 的控制台选择 A 导出的文件，点“两台已有记忆首次配对 → 预览所选文件的合并”。如果已经连接同一百度账号、应用和伴侣标识，可先点“立即同步”；身份保护发现 A 的云端包后，改点“预览网盘中的待配对记忆”，无需手工传文件。
3. 核对两边的消息、记忆和情感事件数量及冲突。预览在事务中模拟后回滚，不改记忆、不上传；期间出现新聊天时需要重新预览。
4. 勾选“两份记忆属于同一个人”，输入“同一个人”，点“备份并合并双方记忆”。B 先保存合并前一致性备份，然后在一个事务内归并身份和数据；中途失败全部回滚。来源原件保留在本机 exports 目录，结果页显示路径。
5. 合并成功后，先在 B 点“立即同步”，再在 A 点“立即同步”。A 导入的是 B 合并后的同主人包，双方之后继续自动同步。没有网盘时，在 B 导出合并后的文件，再在 A 普通导入即可。不要让 A、B 同时互相选择旧文件首次配对。

双方独有的消息、记忆和情感事件会保留；重复导入同包不重复计分。关系由历史事件重建，不直接相加两份好感度。原始关系快照和基线保留在迁移归档中；缺少事件支撑的旧状态无法凭空还原为历史。旧库“全部忘记”的删除记录在配对时固定为已记录的受影响内容，不扩大到另一台后来新增的记忆；已撤回事件不能再次生效。

同一 ID 对应不同原文、事实、事件或删除选择器时，首次配对会阻断，保留双方原件供核对。其他性格分支或设置差异按普通合并记录冲突；结果显示冲突数，有冲突不表示两份状态已经完全一致。当前没有把这种严重身份碰撞自动拆成两条记录的功能。

确认时如仍有生成、发送或后台任务，操作会要求等待结束后重试。备份用于保留合并前证据，不提供一键撤销身份迁移；已有新聊天后不可直接用旧备份覆盖。实际两台物理电脑是否已完成合并，以各自界面结果和同步状态为准。

如暂未重载 DSH，也可以启动同一管理界面：

```powershell
node scripts/memory-transfer.mjs serve
# 按输出的 managementUrl 打开页面；默认读取 desktop profile。
# 验证或隔离环境可传 --config <JSON/YAML配置>。
```

独立入口同样使用配置指向的记忆库；不要让不同版本程序同时迁移同一库。命令行也支持 export、import --file、sync、status。

自动化覆盖真实 HTTP 管理路由、页面脚本按钮流程、完整记忆往返、双设备离线合并与删除传播、长期离线共同基线、上传回读校验、失败重试、令牌刷新及百度 API 请求契约。真实百度账号授权、上传及回读、两个隔离实例离线合并、实际桌面库快照和另一进程启动恢复，以及 DSH Desktop 重启后的启动同步和管理页导出也已通过，详见[验证记录](CLOUD_MEMORY_VALIDATION.md)。两台物理电脑长期使用、自然度与真实 QQ 分别验收。

API 参数依据[百度网盘 SDK](https://github.com/baidu-netdisk/baidu-drive-sdk-go)与其上传/下载实现核对。模型自然度、真人盲评和真实 QQ 使用感受仍按原验收要求执行。
