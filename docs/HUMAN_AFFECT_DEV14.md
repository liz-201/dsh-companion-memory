# dev.14：情境、细分体验与真实运行接线

2026-11-01。目标是提高常见情感场景的覆盖、因果连续性和表达差异，而不是凭类别数量宣称已复现人类。

## 已接入

- 保留全部 22 类 OCC、PAD、心境、稳定人格、关系和联系驱力。全部核心类别都有独立表达指导，避免大量类别最终都压成几种通用态度。
- 增加 18 种可组合的细分解释：好奇、惊讶、愉快、惊叹、平静、无聊、挫败、悲伤、孤独、想念、温柔、怀念、难为情、反感、羡慕、不安、心疼、百感交集。它们是工程解释层，与 OCC 和七个中文显示词有重叠，不能相加成独立的“基本感情数量”。
- 观察器使用 observation-v3，明确情绪对象 concern、原话中的 topic、关键评价轴及未知字段。新增情境轴只在有证据时填写，不能从离线、普通第三方交往或电脑活动推定孤独、失落、吃味。
- 后台观察器不再叠加要求输出 say 的前台协议；优先提供完整结构和必要例子。当前消息附少量同会话前情，用于引用、玩笑和回忆理解；前情只读，不作为本条新事件的来源。
- 同一份原话持续驱动保存、来源回放、PAD、细分体验、表达规划、桌面回复、QQ 回复和主动消息生成。没有再增加一个独立加关系分的情绪系统。
- 表达按对象选择情绪：对软件、物品、工作或剧情的反感不转成对主人的敌意。关系中的感谢和不满可以同时存在；纠正一项来源不会删掉无关的积极感情。
- 前台仍使用原有有界注入；表达计划最多 150 个估算 token。结构化、逐字、代码和任务事实优先。没有开启无候选的模型空转，也没有扩大电脑内容采集范围。
- 面板可查看细分体验、情绪对象和来源；运行接口显示 dev.14 与实际能力清单，不再显示过期 dev.11。

## 真实模型发现的修复

确定性替身不能证明线上抽取遵守协议。本次增加受同源令牌保护的合成诊断：使用当前宿主模型，完全不写原文、记忆或情感事件，不发送聊天消息；只记录模型用量。诊断不读取私人会话。

实测发现并修复了下列问题：

1. concern 在长提示尾部时频繁遗漏；将其放入首要结构，并移除冲突的 say 输出要求。
2. 对象的 appealingness 与事件的 desirability 是不同轴；愉快、惊叹等体验应采用对应对象的有效喜恶信息，不能强求对象评价填事件轴。
3. 明确 pending 的期待无需虚构数值概率；提供有效但非确定的 likelihood 时也可表达未定前景。显式 none、confirmed/disconfirmed 和确定/不可能仍按各自含义处理。
4. 模型有时将既有标量（如 helplessness）放到 situation 内。只规范化已允许的同义位置，数值仍严格校验；同轴冲突拒收，任意未知轴和服务端身份字段仍拒收。
5. 模型有时将合法未知字段名放在 envelope 层。v3 可规范化到各条向量；v2 的旧边界不变。不接受未知字段名或任意解释句子替代字段名。
6. 没有先前偏好或回忆证据时，模型给低置信度可能合理。保留置信门槛，合成诊断补足必要前情，并保留初次失败记录；没有把置信度强行抬高。

诊断案例属于开发校准集，不能当独立验收集；改过提示后取得的结果不等于盲测成绩。实际自然度、角色连续性和情感适切性仍须用户体验或独立人评，代码继续返回 humanQualityVerified=false。

## 研究范围

沿用项目 OCC/ALMA/PAD 与情境评价研究。补充核对 [Cowen & Keltner, 2017](https://pmc.ncbi.nlm.nih.gov/articles/PMC5617253/)：该研究通过视频诱发的自我报告分析类别及其连续过渡，支持不把体验简单压成几个正负轴；不能推出本插件应采用哪些精确阈值，也不证明这 18 个解释是人类全部情感。

所有新增触发阈值、PAD 先验、表达映射仍为工程选择，未作为心理测量值宣传。强度由有证据的评价产生，不由情绪词出现次数或“用户没有及时回复”产生。

## 兼容与数据

- 不新增或改写数据库迁移，schema 仍为 9；旧向量仍可读取。
- 只有含新向量字段或相应历史修订时，导出升级为 portable v6，最低读取版本 dev.14。没有新字段时仍导出 v5。新版本继续读取 1–5。
- 两台电脑若要交换新细分情绪，都需要升级 dev.14。旧读取器明确拒绝 v6，避免部分导入或丢弃证据；不能用旧插件覆盖新库。
- 原文和关键字段缺失的旧评价不会凭空补齐。本次没有批量重抽生产历史。重放只能解释已有字段；需要补历史时必须基于原消息、必要前情和来源验证重新抽取，保留修订。
- 实际切换前通过关闭入口的收尾接口等待队列排空，使用 SQLite backup API 生成一致性备份，并保留旧发行目录和 profile 配置。

## 验证与查看结果

自动测试包含：原有 22 类和七组中文正反例；新增细分体验从真实 coordinator 观察请求到存储、回放和有界表达；缺证据抑制、物品喜恶隔离、混合感情、实际自身行为证据、修订与删除、v6 同步幂等和删除后不复活。使用当前 DSH app.asar 提取的宿主测试材料。

本轮开发工作目录的 `artifacts/` 保留：

- `human-affect-regression.log`：全量自动测试。
- `human-affect-focused.log`：新增功能与边界回归。
- `human-affect-continuous.log`：10,000 条消息、2,500 条迟到评价的一致性和读取不写库测量。
- `human-affect-turn-replay.log`：10,000 轮完整会话回放，failureCount=0；此回放仍为脚本模型。
- `affect-live-*.json`：真实宿主模型的开发诊断，含初次失败及后续结果，未用私人历史。

本轮结果：新增细分体验及来源边界回归通过，完整回归结果以日志最后统计为准；10,000 轮会话回放 failureCount=0。最终连续状态回放中，10,000 条回应和 2,500 条迟到评价重建一致，重复读取写入数为 0，热投影 p95 约 6.7ms、冷投影 p95 约 78.8ms，仅代表本机和这组数据。

15 个真实模型开发场景，经多轮提示和解析修正，均已取得通过来源校验的记录；38 次有记录的开发调用中仍包含协议错误、低置信度、引用前情和网络失败，不能描述为“单轮 15/15”或百分之百召回。选取已通过来源校验的真实模型输出，在最终代码的隔离 coordinator 中重放 15/15 通过，并验证没有发送聊天、表达计划不超过 150 估算 token。该重放没有再次调用模型，详见 `affect-live-output-replay.json`。

可复核命令：

```text
node scripts/build.mjs
node --test "tests/**/*.test.mjs"
node scripts/replay-continuous.mjs
node scripts/replay.mjs --turns 10000
node scripts/evaluate-affect-live.mjs --output=artifacts/affect-live-evaluation.json
```

最后一条会使用当前 DSH 的已配置模型产生实际调用费用。默认只跑内置合成案例，可用 --cases 指定其中的 case ID；它不等于真实聊天自然度测评。
