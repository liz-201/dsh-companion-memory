# 本地记忆整理与来源校验

普通 DSH 会话和 QQ 回合都按数据库中尚未整理的、未删除的用户消息计数。`background.consolidateEveryTurns` 保留原配置名，默认 8；表示每个角色会话积累 8 条用户消息后触发，不要求插件生成回复。桌面后台抽取会另建 `observe:<messageId>` 观察轮次用于审计；整理阈值仍只计算原始用户消息。重复消息、助手输出和内部上下文不增加计数。

本地插件启动时也检查已保存的会话。升级前已经达到阈值的历史可以入队，不必等待 QQ 或凑到某个整除回合。未达到阈值时仍会逐条后台提取事实与情感，不必等整理才能检索记忆。

同一会话有待执行/执行中的整理任务时合并触发，避免每条新消息都增加一次整理调用。成功后按原文序号推进游标；受批次预算限制的剩余消息会继续排队，即使剩余条数低于正常阈值。模型输出缺少合法 changes 数组或游标不前进时任务记录失败，保留原文与游标。失败原因可在 background_jobs.last_error 中检查；首条原文超过整个批次预算时也会明确报告，不能声称已经整理完成。

## 引文校验

实时提取与后台整理统一使用来源匹配：容忍空白、全半角和弯引号差异；不采用语义近似或编辑距离猜测。数字的小数点、否定词等内容不会被规范化删除。匹配成功后，保存的是原消息中的真实片段，不是模型重写的引文。只有标点、空白或者无法在来源中匹配的引文会被拒绝。

整理时逐一核对每个来源消息，并在模型返回后重新检查是否已经删除。提取拒绝原因写入 `evt-applied` 审计的 problems；整理拒绝原因写入 `memory.consolidate` 审计的 reasons。引文匹配只证明引用存在，事实提炼是否准确仍受模型影响，可以用 `/fish memory <关键词>` 检查。

本次没有增加一次失败引文的模型重试，也没有修改逐条提取、主上下文预算或 QQ 桥。整理仍有独立模型费用，正常情况下按阈值成批调用。这里的整理是事实提炼、证据合并与已有冲突处理，不代表实现了基于时间自动归档/删除记忆。

## 验证

新增测试覆盖无 turns 的本地触发、重复消息、待执行任务合并、启动历史补调度、批次剩余续排、不同会话隔离、规范化后的原文证据、多来源与删除校验。实际桌面加载器测试使用模拟模型输出，验证本地消息经过插件入口与后台队列后产生事实，整理任务完成且游标推进；不向真实模型发测试请求。
