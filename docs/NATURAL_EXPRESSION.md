# 情感驱动的自然表达

默认开启 `integration.naturalExpression: true`，不需要额外插件。普通 DSH、QQ 独立回复和主动消息都使用同一套表达映射。人设身份、性别、方言及核心性格仍由原人设决定，不因启用功能而统一变成某种女生或情侣角色。

## 状态怎样影响说话

- 熟悉度、信任与亲近感决定放松程度：初识留分寸，熟悉后减少客套，允许自然多接一句。
- 开心和表达欲影响回应的兴致，温暖程度仍参考稳定性格。
- 生气可以让句子变短、措辞更直接；自控力高的温柔角色保留原来的底色。受伤或戒备时减少玩笑，不强行装热络。
- 信任和熟悉程度足够、没有明显受伤或积怨时，才允许适时接共同用过或明确喜欢的梗；不固定添加脏话、口头禅、撒娇或表情。
- 心情使用按时间衰减后的投影，关系使用已保存的角色状态；不会为了制造戏剧性自动修改关系值。

这些是当轮的表达参考，不是固定台词。不会将“劳资蜀道三”或文档中的示例植入口头禅。用户可以明确告诉角色喜欢哪类玩笑、不喜欢什么称呼；模型在当前语境里自行选择合适措辞。不使用隐私羞辱、情绪施压或假称真人来模拟亲密。

## 语言习惯怎样记住

用户明确表达的长期交流偏好沿用已有 `interaction_rule` 记忆路径，必须有可核对的原话。最多读取当前角色的两条有效交流规则，即使当前话题与规则没有关键词重合也可参与表达。不同角色隔离，群聊规则限制在对应群会话中；过期、撤回和已删除规则不参与。

举例、引用别人的口头禅、单轮格式要求不会被要求记为长期习惯，也不从助手自己的输出反向推断偏好。普通本地会话的提取仍在后台运行，因此刚表达的新偏好通常在后台完成后的后续回复里稳定生效；当前回复仍可直接遵循本轮要求。

## 减少报告式说话

闲聊通常先接眼前这句话，一到三句即可；避免标题、编号、加粗总结和惯性满意度追问。心情和关系体现在表达里，不复述“普通偏熟、基本信任”等标签。技术任务、明确的详细解释、列表和其他格式要求优先，不因情绪而敷衍任务。

普通 DSH 开启本功能后，注入表达指引替代直接的心情等级段；`/fish mood` 等诊断命令仍可查看状态。完整接管提示词的预设通过 required runtime context 接收表达参考，原人设正文不修改。

## 开关与预算

```yaml
- id: dsh-companion-memory
  name: dsh-companion-memory
  config:
    integration:
      naturalExpression: true
      contextBudgetTokens: 450
```

设为 false 关闭本层，记忆、情感计算和同步继续工作。本地注入仍受原有总预算限制，表达指引最多使用约 55% 的预算，为设备信息和记忆留空间；按完整行取舍，不把一句限制截断。极小预算或很长的记忆会导致部分指引/记忆无法进入当轮。

该映射不调用模型、不重写已生成的回复，因此没有新增的一次“润色调用”。提示词内容改变仍可能改变实际 token 用量；后台提取和整理原有费用照常存在。QQ 独立生成继续受整个输入的硬预算限制。

## 验证与效果边界

测试覆盖关系变化、心情变化与衰减、原性格保留、关闭开关、无关键词时交流规则召回、角色隔离、预算、QQ 单次模型调用，以及实际桌面提示词组件中的完整预设兼容性。测试验证状态和提示词接入，不代表真实模型一定说出某句自然台词。

模型能力、其他人设指令以及会话已有风格仍会影响表达。建议重启后在新会话或新一轮试几种日常话题，观察实际语气，再调整原人设或明确交流偏好；不要仅凭一句回复判断关系是否改变。
