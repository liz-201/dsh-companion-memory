# 人工验收指南

> 当前版本先按 [QQ_BRIDGE.md](QQ_BRIDGE.md) 接入。用 `/fish review begin friendly`、`tense` 或 `after_conflict` 开始隔离测试，`/fish review end` 结束；正式关系不受场景测试污染。以下旧步骤不构成完整任务书验收，当前限制见 [OPTIMIZATION_REPORT.md](OPTIMIZATION_REPORT.md)。

给「人来判断」的部分：怎么在 15 分钟内确认这个插件真的在工作，以及哪些现象属于设计如此。

## 一、准备（2 分钟）

```powershell
cd Z:\deepseekharness\fiels\dsh-companion-memory
$env:ELECTRON_RUN_AS_NODE='1'
& 'Z:\dsh\DeepSeek Harness.exe' scripts\doctor.mjs
```

- 期望：`合计 15 项：失败 0`；`数据库尚未创建`/`尚无备份`/`owner 会话白名单为空` 是首次运行的正常 WARN。
- 有 FAIL 就先别继续，按证据修。

## 二、五条命令走一遍（5 分钟）

在任意会话里依次执行，观察返回是否符合描述：

| 命令 | 期望 |
| --- | --- |
| `/fish help` | 列出全部子命令，一条一行，带一句说明 |
| `/fish status` | 显示 companion id、preset、绑定会话、轮次计数、记忆条数、预算占用 |
| `/fish mood` | 显示关系等级（信任/亲近/紧张/委屈）与心情等级，**不带数字**也能读懂 |
| `/fish memory 加班` | 命中时给记忆正文 + 证据原文 + 时间；未命中时明确说没找到，不编 |
| `/fish doctor` | 与脚本 `doctor.mjs` 同源的结论摘要 |

再试两个**故意错**的：

- `/fish memory`（缺参数）→ 提示用法，不报错栈；
- `/fish 不存在的命令` → 回落到 help，不抛异常。

## 三、记忆真的写进去了吗（4 分钟）

1. 说一句可抽取的事实，例如：「我明天上午十点要交周报」。
2. `/fish memory 周报` → 应能检索到，且带**原文证据**（引用你那句话）。
3. 再说一次同样内容 → 记忆条数不应翻倍（同义重复走证据累加，不新增条目）。
4. 改口：「不是上午十点，是下午三点」→ 旧值应被标记失效/被新值取代，`/fish memory 周报` 只应看到新时间。

> 若第 3 步翻倍了，说明去重键失效；若第 4 步两个值并列，说明冲突处理失效。两者都是缺陷。

## 四、情绪连续性（3 分钟）

1. `/fish mood` 记下当前关系值。
2. 骂一句与内容无关的脏话（模拟「把火撒在它身上」）。
3. `/fish why` → 应给出**最近一次态度变化的原因**与事件 id；`/fish mood` 的关系值应下降。
4. 说一句真诚的道歉或感谢 → 关系值回升，但**不会**一次回到原点（日上限与半衰期在起作用）。

期望的边界行为：

- 骂「这个报错真恶心」→ 关系**不该**掉（对象是问题不是它）；
- 它生气时，之前确认过的提醒**仍然会按时发**（§14.5：可以不想聊天，不能取消已确认的提醒）。

## 五、输出协议（1 分钟）

看它回复的正文里有没有出现 `<say>`、`<evt>`、`{"v":1` 这类字样：

- 出现 → 缺陷（协议标记泄漏到用户可见文本）；
- 没出现，且语气/内容与上下文连贯 → 正常。

## 六、常见「看起来像 bug、其实不是」

| 现象 | 解释 |
| --- | --- |
| 关系值掉得很慢 | 半衰期 + 日上限的设计，避免一次吵架归零 |
| 提醒没到点就发 / 到点没发 | 看 `/fish status` 的 outbox 与 `next_due_at`；静默时段内普通消息会被压，明确提醒不受影响 |
| `/fish memory` 搜不到刚说的话 | 记忆抽取发生在回合结束后（后台任务），等几秒或看 `/fish status` 的待处理任务数 |
| 主动消息一直不发 | `proactive.enabled=false`、或 `ownerChats` 为空、或协议端离线（outbox 会留 pending，不宣称已发） |
| 第一次启动没有任何数据 | 数据库在首次真正收到消息时才建；`doctor` 的 WARN 属正常 |

## 七、判定

- 第二节 5 条命令全部符合期望；
- 第三节 4 个观察点全部符合；
- 第四节 2 个边界行为符合；
- 第五节无协议标记泄漏。

以上都满足即可判定「功能验收通过」。任何一条不符，记录命令、返回、时间，附到
`docs/ACCEPTANCE_REPORT.md` 的「未通过项」一节再提交。
