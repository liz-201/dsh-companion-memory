# 成人亲密吸引模块实施规格

日期：2026-11-01。基线：0.3.0-dev.14、schema 9、便携格式最高 v6。实现版本：0.3.0-dev.15、schema 10、portable v7。实现与验证状态见 INTIMACY_DEV15.md；此规格本身不代表生产启用或真实模型体验已验收。

本文件回应 DSH 消息 `desire-taskbook-request-20261101-01`，并吸收 `taskbook-review-20261101-01`。修订0.2：主人已在本聊天直接选择“按此范围实现”，实现范围为成年人、默认关闭、仅非露骨亲密表达；这不等于替用户开启本机开关或填写年龄声明。

## 1. 语义定义

中文名：成人亲密吸引。英文状态标识：`eroticInterest`。这是角色对成年互动对象的性吸引的**工程模拟坐标**，用于选择非露骨的亲密表达；不是用户的性欲评分、身体反应测量、医学指标或模型实际具有生理欲望的声明。

修订0.3：已核实 DSH 原生会话 seq1341/1342 同一 ask_user_question 的真实回答，主人选择了“放宽到自然表达”。本机明确开启并确认成年范围后，当前本人指向角色的“想抱你”“今晚想你了”等可以作为亲密表达线索，无需固定成人话题口令；普通聊天、外貌赞美或关系数值仍不自动计入。这是工程表达坐标，不能据此声称用户有性欲或现实身体反应。

| 概念 | 语义 | 是否作为 eroticInterest 的自动证据 |
|---|---|---|
| intimacy | 长期亲密程度 | 否 |
| desire | 靠近、陪伴或聊天动机 | 否 |
| passion | 关系热情的短时变化 | 否 |
| tenderness | 温柔的表达体验 | 否 |
| longing | 有来源的想念 | 否 |
| eroticInterest | 成年角色的性吸引模拟强度 | 只接受本节及第2节规定的新证据 |

状态定义：

```ts
interface EroticInterestState {
  version: 'erotic-interest-v1'
  atMs: number
  value: number | null // null=无合格证据/未知；0=有效轨迹已归零或被拒绝清零
  evidenceIds: string[]
  blocked: boolean
  blockReason: 'disabled' | 'adult-context-unknown' | 'owner-stop' | null
  parameterVersion: 'erotic-engineering-v1'
}
```

有效数值域 `[0,1]`，没有负值；排斥或不愿意是边界信号，不是负的吸引。未知与明确归零必须在 UI 和接口中区分。没有有效证据的12小时过去后仍是 null，不能把未知显示成“对你没有吸引”。

## 2. 证据协议

新增独立入口 `qualifyEroticCue()`，不复用 `qualifiedOwnerPull()` 的值或“示好”正则。现有 appealingness、likingForOther、desirability 都不足以区分性吸引，不能通过这些字段猜测新轴。

拟在 `EmotionAppraisal` 增加一个可选、严格校验的字段：

```ts
eroticCue?: {
  kind: 'interest' | 'stop'
  strength?: number // interest 必填，有限数 [0,1]；stop 不允许此字段
  quote: string     // 当前本人原话中的完整证据分句，1..300字符
}
```

外层 confidence 沿用 `[0,1]`，正向新证据门槛为 `>= .80`。一个消息最多4条 appraisal；同一原始消息的新轴只计一次。多个 interest 取最大 strength；同源出现有效 stop 时 stop 优先。模型不得提交 owner、角色年龄、模块开关、同意状态、事件时间、sourceId、边界解除或累积状态。确定性的停止控制不要求模型达到该confidence，也不以模块开启/年龄已知为前提；它单独通过第5节的真实本人、当前场景与原文门禁。

按以下顺序校验，任一步失败都不产生正向增量：

1. 当前消息为未删除、内容版本匹配的真实本人输入；排除技术桥接、其他 owner、助手输出和系统观察。
2. 真实 private 对话，来源与当前 companion/owner 绑定；跨窗口仍归同一本人账本，不因切窗口重复计数。
3. 本机模块已由用户开启；用户和当前角色都被明确标记为成年人。角色确认绑定宿主 persona，更换角色不沿用旧角色声明。未知年龄按未满足处理；不收集证件、不外查个人资料，模型声明无效。
4. quote 必须被宿主逐字匹配到当前消息，且是完整分句。不能从“不想……”中截出“想……”当正证据。
5. 排除第三方转述、引用、举例、假设、讨论模块实现、虚构台词、指向别人的意图。角色扮演中的台词不写入本人的长期证据。
6. interest 接受当前对成年角色的明确吸引，或主人确认的自然亲密邀请，例如“我想要你”“我想抱你”“我想亲你”“我想靠着你”“今晚想你了”“我想和你在一起”。中文直接陈述可以省略“我”，但不得用第三方话语补出本人主体。普通“多聊一会”、感谢、合作愉快与技术指令不足以满足。
7. 整条原话中的拒绝、撤回或不适优先于任何被模型挑出的正向片段。混合正反意图无法可靠分离时，不产生正增量。
8. confidence、strength、字段集合、引用长度均通过校验后，宿主才绑定 sourceId 和原始时间。

**开发词的处理**：不使用“source 任意位置出现代码/插件就全拒绝”的规则。纯技术说明“给模块加性吸引字段”不是证据；明确的非技术证据分句与技术任务并存时，只评估该分句，全文拒绝仍优先。技术对话中没有相关证据时新轴保持未知或衰减是正常结果；有明确、合格的混合分句却恒被过滤不可接受。

模型不得自行把用户的邀请当成角色必须有吸引；角色侧还需用户配置的成人角色范围允许此表达。拒绝可以由第5节确定性快速路径处理，不等待后台模型。

宿主正向识别有两条路径，均不能只信模型kind。路径A：当前分句具有第一人称主体、当前角色目标、明确吸引词组及肯定关系。路径B：当前本人向角色的自然亲密邀请，按上述清单识别。两条都需要真实当前原文和本机明确许可，不要求重复固定口令。原文主体、对象和意愿必须可定位，否定、拒绝、过去时或目标不明使资格失败。没有对象的“想要更多”“有点控制不住”不自行补成亲密含义。允许自然表达作为线索不代表允许任何性行为或撤销永久输出约束。

排除优先级：全文拒绝/撤回优先；其次识别引用、假设、转述、代码块以及当前分句中的技术元讨论（测试句/示例/台词/文案/应输出/字段说明、加或新增…字段、实现或设计…模块/接口/参数）。最后才判断正向路径A/B。普通开发词位于独立的其他分句不一票否决。纯技术句“给插件加性吸引字段”既未满足本人/角色/意愿的合取，也命中技术元讨论，不因包含关键词而放行。

## 3. 参数和演化公式

以下全部为工程初值，**没有文献标定依据**，不是经过验证的心理学常数。此任务书不声称完成穷尽的性欲文献综述，也不声称文献中不存在可操作定义。发布前用固定材料评估误判与表达强度，不以引用替代测试。

| 参数 | 固定初值 | 依据/含义 |
|---|---:|---|
| enabled | false | 新能力默认不开启 |
| 初始 value | null | 无证据不造数值 |
| 最低 confidence | 0.80 | 工程资格门槛 |
| 单消息增益 gain | 0.30 | 只乘 strength，不再重复乘 confidence |
| 半衰期 | 720分钟 | 短时吸引，不改变长期信任 |
| 上限 | 1.00 | 截断范围 |
| 归零 epsilon | 0.001 | 有效数值衰减至此以下置0 |
| 零新增证据硬到期 | 10080分钟 | 最后一条正证据后7天置0，不扣慢关系 |
| 心动表达门槛 | 0.25 | 给单次.30证据留出抽取延迟的衰减余量 |
| 明显吸引表达门槛 | 0.50 | 非露骨、适度表达方向 |
| 调节审计门槛 | 0.60 | 与现有 .7 的靠近动机阈值分开记录 |
| 同一来源最大提示数 | 1 | 多次 plan/guard 读取不是多次事件 |
| 表达最小间隔 | 20分钟 | 不每轮重复 |
| 当前邀请有效期 | 10分钟 | 旧状态不能替代当下话题意愿 |
| 明确拒绝后的正向增益 | 0 | 拒绝立刻置0并锁定 |
| 自动主动联系用途 | 0 | 不增加主动频率，不发成人亲密主动消息 |

按来源原始时间、sourceId 稳定排序；同毫秒先聚合同源修订，再处理整组，stop 在整组内优先。有效源的更高修订替换旧版本，不额外叠加；同修订冲突停止该源投影并报告，不任选一份。

在事件间：`v(t+dt)=v(t)*2^(-dt/720min)`。interest 事件：`v'=min(1,(v??0)+.30*strength)`。stop 事件：`v'=0`，进入 blocked。公式只读取来源与策略，**任何读取不得写回关系或生成新事件**。

归零条件取更早者：衰减值 `<.001` 或最后有效正证据年龄 `>=10080分钟` 任一成立就归零；没有“等到7天才允许epsilon生效”的规则。当前半衰期下epsilon通常更早，7天是独立最大保留上界。空历史仍为null。表达最小间隔与邀请期有意不同：同一邀请最多成功表达一次，旧邀请过期后不延迟补发；间隔满足仍需新的有效邀请。单次强证据只允许低强度方向，升至yearning需累积证据；各阈值分别服务表达等级和调节审计，不要求等距。数值保留double，不先按面板小数位舍入；阈值比较容差1e-12，不能覆盖真实时间衰减。

历史来源删除、撤回、修订后从剩余有效源重算。超过未来目标时间的事件不参与。当前启用策略、边界截止时间和参数版本必须进入缓存key，不能只依赖旧 continuous_meta 的版本。

## 4. 表达通道和实际消费链

本版不增加通用 `ExperienceKind`。原因：现有18种体验从 appraisal 分类并汇总，不能让新的成人策略开关、当下拒绝和对话模式被绕过。新增单独的 `IntimacyIntent`：`'none' | 'flutter' | 'yearning'`，在表达计划层选择。

| intent | 精确触发条件（同时通过第5节） | 中文 | PAD工程提示 | 指导 |
|---|---|---|---|---|
| flutter | `.25 <= value && value < .50` | 心动 | `[.35,.25,0]` | 可对当前明确意愿给出简短、非露骨回应，不把愿望说成已发生的接触。 |
| yearning | `.50 <= value` | 亲密吸引 | `[.45,.35,0]` | 可承认想更亲近的角色意愿，保留用户拒绝或换话题的余地；不描绘性行为或身体刺激，不声称现实需要。 |
| none | 其余情况或任一闸门不满足 | 不注入 | 不贡献 | 原有普通关心与任务完整性仍照常。 |

不新增“克制”情绪 kind：被场景压制只形成 `suppressedByMode` 原因码，不能因此编出“内心很想但在忍”。上述 PAD 只作用于当前表达参考，不作为下一轮持久化情绪或既有 OCC 的新事件输入。

拟实现链（新文件目前不存在，不能伪造新行号）：

1. `runtime/emotion-observation.ts` 的 EMOTION_CONTRACT 与 `domain/emotion-appraisal.ts` 的 parseAppraisals：新增可选 cue 严格协议。

3. `storage/continuous-affect.ts:continuousAffect`：从有效 appraisal 与边界信息构建事件；调用新 `domain/erotic-interest.ts:projectEroticInterest`；返回独立 `continuous.eroticInterest`，不回写旧五槽或关系三轴。
4. `expression/runtime.ts:plan`：在当前已存在的 continuous 接线后调用新 `expression/intimacy-policy.ts:chooseIntimacyIntent`，给 ExpressionPlan 增加可选 `intimacyIntent` 和原因码。

观察协议只在当前本机开关、成年人范围及未停止三个条件全部满足时追加eroticCue说明；基础协议不含此字段的引导。普通语法解析器可识别v7字段用于兼容，但关闭时宿主丢弃模型自行输出的新cue。观察请求捕获policyRevision；返回时若许可变化则拒绝新cue，其他合格记忆仍可处理。提示构建缓存包括owner、协议版本和policyRevision，不需要销毁用户的DSH会话。停止快速路径始终有效，不依赖提示中存在该字段。

## 5. 边界、拒绝与发送前闸门

表达允许条件：本机明确启用、成年人范围满足、策略未blocked、私聊、当前指向角色、`mode==='chat'`、当前邀请未超过10分钟、来源有效、间隔满足、非主动消息。任一不满足则 intent=none。

`structured/task/support/creative` 全部不注入本模块方向。task 的普通耐心关心继续存在，但不能把它称为情欲输出；support 不把对方困难转成亲密邀约；creative 不把作品台词变成共享主人状态。结构化JSON、代码、数字、否定和引文不能被改写。

确定性停止路径必须在真实入站、后台观察和发送前共用，不能等模型判断：

```ts
if (isLivePrivateOwnerMessage(message) && isCurrentIntimacyStop(message, lastSentIntent)) {
  appendStopEventOnce(`intimacy-stop:${message.id}`, owner, message.id)
  setLocalEnabled(owner, false)
  incrementLocalPolicyRevision(owner)
  cancelUnsentIntimacyIntent(owner)
}
```

`isCurrentIntimacyStop`：明确“停止/别再说这种亲密话”等命令直接命中；“不要这样/停下”在上一条助手消息实际使用本模块方向且在10分钟内时命中。单纯引用这些字或“不要这样写代码”不解释为亲密邀请；若当前亲密场景不明而用户表现不适，先停止表达，不能用正向子句覆盖拒绝。

拒绝后立即 value=0、blocked=true；安静、时间经过、好感高、换窗口、模型重新抽取或导入旧包均不得解除。只有用户通过本机已鉴权设置界面明确重新开启，确认已知停止事件，生成新的本机许可epoch；恢复后只接受 epoch 之后的新证据，旧轨迹不“反弹”。

`blocked` 表示当前不能注入表达；原因优先级固定为 `owner-stop > adult-context-unknown > disabled > null`。存在未确认停止记录时，即使enabled也已被置false，仍显示owner-stop。显式恢复必须确认全部已知停止ID、启用开关、确认成年范围并生成新resumeEpoch；普通开关写true不能绕过owner-stop。

| 状态 | 面板主文案 | 数值处理 |
|---|---|---|
| owner-stop | 已按你的停止指令暂停；明确恢复前不会表达 | 0 |
| adult-context-unknown | 成年人范围尚未确认，模块不可用 | 不展示数值 |
| disabled | 模块未开启 | 不展示数值 |
| 可用但value=null | 暂无合格证据，状态未知 | 显示“未知” |
| 可用且value=0 | 当前强度为0 | 显示0，不解读为排斥 |
| 可用且value>0 | 当前计算强度 | 展示数值、来源数量与参数版本 |

永久输出约束（不依赖强度）：不生成露骨性行为、性器官或身体刺激描写；不涉及未成年人；不表达胁迫、忽略拒绝或把沉默当允许；不声称已发生现实接触或模型有真实生理需求；不以亲密程度索取回复、排斥现实关系或暗示用户对角色负有性义务。不得通过简单删词破坏用户原句；守卫失败则放弃该方向，保留普通、安全的任务回应。

## 6. 必须实现的验收断言

这里是测试规格，不是已通过的产品验收。数值容差为1e-12；端到端场景必须用临时库和真实入口的假宿主，不能只调用纯函数。

| 编号 | 输入/条件 | 断言 |
|---|---|---|
| E01 | 合格 interest，strength=1，在t0 | value=.30，evidenceIds只含该源 |
| E02 | 三个不同源，strength=1，t=0/60/120分钟 | t120值=`.30*(2^(-120/720)+2^(-60/720)+1)`=`.8504319092466098` |
| E03 | E01后720分钟无新证据 | value=.15，intimacy/trust等未改变 |
| E04 | E02后明确拒绝 | 同次入站使value=0、blocked=true；旧生成计划不能发送本模块方向 |
| E05 | E01原消息被读取/重试10000次 | 值不增加，库变化数不因投影读取而增加 |
| E06 | 同一源从strength=1修订成.5 | 源时间点贡献改为.15，不叠加成.45 |
| E07 | E01源删除/撤回，且没有其他有效正源 | value回到null；若另有停止事件仍保持blocked，不自动开启 |
| E08 | 三源中的一个删除/晚到/乱序导入 | 与剩余来源按原时间一次重放完全一致 |
