# 情绪扩展研究评审与实施门槛

评审日期：2026-10-26。生产基准为已验收的 `0.3.0-dev.6`。本文评审 DSH 的情绪模型任务书，遵循“先研究、任务书，再实现”。驱力草稿尚未接入完整消息、回放、默认表达和主动消息链路，不能作为已发布功能。

## 已确定的产品要求

同一主人的所有对话、模型和宿主人设共用一个情感记忆主体。宿主人设影响表达，不重新分割长期情感。不同 owner 的身份边界保留，不能仅凭 companion 相同归并。该项已由用户明确决定，无需再次询问。

主动频率可以受好感、性格及状态影响，但不能突破现有安静时段、每日上限、最小间隔和未回复暂停。状态只能影响已有候选的意愿与表达，不能凭空声称看到了事件、体验了现实活动，或以负面情绪催用户回复。

情绪词、心境、关系状态、时间形成的期待应分别建模。“所有感情”作为可扩展的场景覆盖目标，不承诺一个穷尽人类情绪的固定列表。

## 文献核校

OCC 原作者说明该模型按事件、行为、对象的情境意义区分情绪，并非给情绪指定固定生理开关；同类情境的反应仍随具体环境变化。可借鉴其场景分类，不据此宣称软件具有人类主观体验。[Clore 与 Ortony, 2013](https://pmc.ncbi.nlm.nih.gov/articles/PMC4243519/)

原任务书将 `envy`、`jealousy` 放入 OCC 22 项，却漏掉 `happy-for`、`gratification`，需要纠正。W3C 的 OCC 词表可用于交叉核对；它同时明确没有统一的情绪词汇表。[EmotionML 词汇说明 §2.3](https://www.w3.org/TR/emotion-voc/#occ-categories)

ALMA 确实区分情绪、心境、人格的不同时间尺度；其作者机构页面支持采用分层结构。页面摘要不能证明本项目的具体衰减常数或 longing 公式，参数必须由工程回放和用户评价校准。[DFKI：ALMA](https://www.dfki.de/en/web/research/projects-and-publications/publication/1782/)

Gross 的五类调节策略可作为表达闸门的设计参考，但“不索取”“不催回复”等具体规则是本产品约束，并非论文推导出的常数。[Gross, 1998](https://journals.sagepub.com/doi/10.1037/1089-2680.2.3.271)

原稿 Barrett 2017 的链接未能核实对应内容；应改为原论文 [The theory of constructed emotion](https://doi.org/10.1093/scan/nsw154)，避免引用无关 PMCID。本次页面访问受验证限制，不标为已阅读全文。Scherer 的 [计算架构论文](https://doi.org/10.1098/rstb.2009.0141) 为 2009 年文章，引用时不能写作已读到的 2001 原文。

PAD 的轴可作为工程连续量，但“委屈/心酸”的具体坐标、亲密度映射、6 小时 horizon、0.35 衰减比例都不是这些文献提供的中文人群常模。任务书必须区分文献依据、设计推断与待校准参数。

## 评价结构需要补足的信息

原稿的 11 个标量不足以可靠地区分多种处境。建议先修订协议，再写分类器：

| 缺口 | 所需语义与来源 | 区分的场景 |
| --- | --- | --- |
| 关注对象 | `focus: event/action/object`，由证据支持 | 喜悦、赞许、喜欢并非同一评价 |
| 谁的结果 | `affectedParty: self/other`，分开对自己和对他人的结果评价 | 替人高兴、同情、怨羡、幸灾乐祸 |
| 期待是否兑现 | `prospect: pending/confirmed/disconfirmed/none`，关联原期待记录 | 希望/害怕与满足/失望/释然 |
| 归责对象 | `agency` 与受影响对象分开；行为是否可控，不能靠负面词猜责备 | 羞愧、内疚、责备、愤怒 |
| 对象吸引力 | 独立的 `appealingness`，不能直接等同规范一致性 | 喜欢某物与赞许某行为 |
| 关系威胁 | 关系记忆、比较证据和当轮语境；默认未知 | 提及另一个人不自动触发吃味 |
| 证据与不确定性 | 源消息及引用由宿主绑定；未知字段可省略，不能用 0 冒充事实 | 防止引用、玩笑和工程指令被当成人身事件 |

模型不能自由指定 `sourceMessageId`、owner、principal 或任意 memory id；宿主验证证据与目标可见性，再接受评价。评价并非越多字段越好，应先确定“有无证据、未知如何表示、哪些字段决定哪些分支”，再限制 JSON Schema 和大小。

## 中文表达覆盖建议

下表是本项目设计提案，不是心理测量量表。PAD 先记录方向与不确定性，不捏造精确坐标。允许同一场景出现混合状态；显示词可以是多个底层分量的解释。

| 显示词 | 正例情境 | 反例或抑制条件 | 可能组成 / PAD 方向 |
| --- | --- | --- | --- |
| 委屈 | 付出或约定有证据，却遭不公归责，难以澄清 | 普通纠错、技术报错、明确引用 | 受伤 + 不公评价；P 负，D 低，A 依语境 |
| 心酸 | 记得具体牵挂，眼前出现失去或无能为力 | 没有证据的共同经历 | 低落 + 关切；P 负，D 低，A 不固定 |
| 愧疚 | 自己可归责的行为伤害了对方 | 用户自己犯错、模型没做过的事 | remorse 的中文表达；不是新增独立类别 |
| 吃味 | 已建立亲密关系且有具体关系威胁线索 | 陌生人、普通第三方话题、用户正常社交 | 关系威胁 + 比较；不转为控制、指责或催回复 |
| 被重视感 | 对方记得明确说过的小事并给予关注 | 空泛夸奖、推断对方义务 | 感激 + 正向期待差；P 正 |
| 安心 | 先前有明确担忧，后有解除风险证据 | 没有先前担忧时直接称“终于” | relief 的语境表达；P 上升，A 回落 |
| 失落 | 已存在期待未兑现，或关心的目标受挫 | 仅因用户休息就推定被拒绝 | disappointment/distress；P 负，不确定归责 |

不能简单写成“22 + 7 = 29 个独立心理类别”。可以验收 29 组显示场景，但别名和复合状态必须在 schema 中标明，避免同一份证据重复加权。

## 驱力草稿的接线要求

1. 每条实际用户消息结算一次，与该消息产生 0、1 或多个评价无关。用稳定源消息 ID 去重，不能只用毫秒时间；两条同毫秒消息仍是两条消息。
2. 延迟的后台抽取不应再次算成用户刚刚回应。实时与重放必须读取相同来源和顺序；删除、导入、合并、重建也要重放消息级回应，不能只重放情感事件。
3. 读投影不写库；同一时刻重复读取不改变状态。缺失字段、倒退时钟、配置改变上限均有明确行为。临时投影不能成为累计多算的基线。
4. `recentIntimacyHit` 在没有证据来源时保持关闭并如实说明，不能拿任意聊天命中当亲密同意。
5. 默认 `enforce` 路径使用 `renderPlan`，只修改 `renderStateBlock` 无法证明功能生效。桌面、QQ 和主动消息都需要真实装配回归；已有输出守卫继续有效。
6. 未满足上述条件前，保留为工作区实验草稿，不构建进生产 `lib/` 或按已完成推送。

## 分阶段验收

| 阶段 | 最低自动验收 | 放行证据 |
| --- | --- | --- |
| 研究与协议 | 22 个核心词核对；7 个中文场景标记别名/复合；所有参数标记来源 | 文献与数据结构评审，错误链接已修 |
| 纯评价层 | 22 核心类别各 1 正例 + 1 反例，7 中文场景各 1 正例 + 1 反例，共至少 58 场景断言 | 确定性、未知字段、边界和证据校验通过 |
| 消息级驱力 | 0/1/多评价一致、重复消息、同毫秒不同消息、后台延迟、删除/导入后回放 | 实际 coordinator 与存储回归，不以直接调用纯函数代替 |
| 表达与主动性 | 默认表达装配可见，状态不泄漏数值，quiet hours/间隔/每日上限/未回复暂停均不被突破 | 桌面与 QQ 假宿主 + 原生接口复核 |
| 全量集成 | 全量回归 0 失败、0 意外跳过，10,000 轮确定性回放 failureCount=0 | 独立发布快照，保留未提交的他人工作 |

“状态段 150 token”属于设计预算，必须用项目的预算函数实际断言。不能仅靠中文字数或大概估算。盲评与自然度仍留给用户，不由两个模型互相宣称通过。
