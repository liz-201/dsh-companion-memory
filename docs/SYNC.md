# 跨电脑记忆与情感同步（0.2.0）

2026-10-25 开发版修复：后台同步周期改为 storage.syncIntervalSeconds（默认 300 秒，30–86400 秒），启动、关闭和手动 /fish sync 仍可立即导出。无数据库变化时跳过全表扫描。portable_checkpoints 保留最近 8 份不同内容，通常总量不超过 1 MiB；单份超过上限时保留最近一份完整基线。轻量 package receipt 独立保留，防止裁剪后导入自己的旧文件；v2 格式不变。清理只释放 SQLite 可复用页面，不立即缩小物理文件。详细验证见 [_exchange/FROM_CHATGPT/DELIVERY-B5B1-20261025.md](_exchange/FROM_CHATGPT/DELIVERY-B5B1-20261025.md)。

安装并启用插件后，普通 DSH 会话默认记录用户原话、回复、长期记忆和情感变化，不需要 QQ。模型回复仍由 DSH 原本的流程生成；插件通过后台模型调用提取有证据的记忆与情感，通常在消息写入后的下一次后台轮询开始（约 5 秒，另加模型耗时）。没有可用模型时原话仍保存，提取失败会显示在诊断状态中，不会虚构情感更新。

## 最简单的换电脑方法

1. 在旧电脑的普通 DSH 会话输入 `/fish sync`。它立即生成最新迁移文件，并返回完整路径；默认在 `%USERPROFILE%\.dsh\companions\transfer\`。等待后台提取完成后导出，才能带上刚刚产生的情感；尚未完成的提取任务也可随文件迁移。
2. 把这个 `*.companion.json` 文件通过网盘、U 盘或直接复制，放到新电脑同样的 `transfer` 目录。
3. 新电脑安装同版本插件，使用同一个 `companion.id`，启动或重启 DSH。插件在接收新对话前自动校验并合并记忆。首次迁移建议在新电脑开始聊天之前完成。
4. 在普通 DSH 会话输入 `/fish sync` 可以查看当前电脑识别结果。模型每次组装本地会话上下文也会获得电脑名称、系统版本、架构、时区和“新电脑 / 回到旧电脑 / 仍在当前电脑”的判断。

回到旧电脑时，把新电脑产生的文件也复制回去，然后重启 DSH。已有的旧文件可以留在目录里：导入有持久化去重。插件每隔 60 秒检查变化并更新本机迁移文件，正常卸载时也导出；`/fish sync` 可立即导出。文件名包含角色与电脑标识，不同电脑不会覆盖彼此的文件。

这是**启动时合并、运行时导出**，不是实时联网服务。文件在 DSH 运行期间到达时，下一次重启才导入；没有通过网盘或拷贝传递文件，就不会得到另一台电脑的新记录。

## 使用网盘文件夹

在每台电脑的 profile `cordis.patch.yml` 配置它自己的网盘本地路径：

```yaml
- id: dsh-companion-memory
  name: dsh-companion-memory
  config:
    storage:
      transferDirectory: 'D:/我的网盘/DSH记忆'
```

只把 `transferDirectory` 放进网盘。`storage.directory` 保持每台电脑本地独立，不能让两台正在运行的 DSH 共用一个 SQLite 数据库。迁移文件有完整性校验、临时文件写入和原子替换；尚未下载完整的文件会被拒绝并在下一次启动重试。网盘目录不可访问会报告同步失败，本地会话仍可记录记忆。

迁移文件包含聊天原文和个人记忆，使用你自己的私有存储；文件不加密。自动文件只包含数据，不含模型凭据、QQ Token 或插件程序，新电脑仍需安装插件与配置模型。

## 合并规则与限制

- 同一主人身份随数据迁移；本地会话和白名单内的 QQ 私聊共用主人记忆与关系。群聊仍受独立作用域限制。历史上同时含群聊与私聊的旧身份不会自动折叠，以免改变其隐私边界。
- 独立新增的消息、记忆与情感事件合并；双方发生分歧的情感投影按事件重算。瞬时心情继续随现实时间衰减，不会把旧电脑导出时的愤怒永远冻结。
- 同一条事实被双方改成不同内容时保留本地值，并把另一版本记入 `portable_conflicts`，不静默覆盖。普通会话 `/fish status`、诊断 `/companion-memory` 的 `status.sync.imports` 和日志会报告冲突数；当前没有自动语义裁决或冲突编辑界面。
- 已存在聊天数据且主人身份不同的数据库拒绝自动合并。若两台电脑在第一次迁移前已分别开始使用，会生成不同主人身份；此时可把目标 `storage.directory` 改成新的空目录再导入，原目录的数据会保留。
- 导入前自动备份；旧出站队列不会再次发送，导入的已确认提醒暂停为待确认。后台情感提取可恢复，其他后台任务不重放。
- 同步包上限为解压后 256 MiB。超限会报告失败；本版未实现分片与无限增长历史的增量网络同步。
- 电脑标识使用操作系统机器 ID 的哈希，不随数据库一起固定在旧电脑。重装系统可能视为新电脑，完全克隆操作系统的设备可能被视为同一台；读取失败时使用主机名回退并明确提示。

也可以在**两端 DSH 完全退出后**复制完整数据库到空目标目录；必须保证 SQLite WAL 已完整提交或一并保留。推荐使用迁移文件，因为它支持两端已有数据的合并和自动备份。

## 开关与验证

`integration.enabled`、`integration.localOwner` 默认都是 `true`。关闭任一开关可停止普通 DSH 会话接入；`integration.excludedAgentIds` 可排除指定 Agent。只观察 `source.kind=user` 的真实用户消息，工具结果、系统上下文与自动任务不会伪装成用户情感来源。默认给模型增加最多约 450 token 的上下文，可通过 `integration.contextBudgetTokens` 调整。

接口按本机安装的 DSH 实现核对：`agent/inbox/claimed`、`session/event`、`system-prompt/assemble`。使用这些接口的宿主可默认生效；旧版本若不发送这些事件，普通会话接入不可用，需要更新宿主。`ctx.on` 存在只说明可以订阅，不证明事件实际发生。

验证命令：

```sh
node scripts/build.mjs
node --test "tests/**/*.test.mjs"
```

新增测试覆盖普通会话记录与后台提取、关闭开关、排除 Agent、新旧设备识别、启动导入、重复文件、损坏文件、双端分支合并与不同主人拒绝。真实网盘客户端与两台物理电脑上的端到端运行仍需实际使用验证。
